# ④ 행 단위 재사용 측정 계획 (실행 전 기록, 2026-11-09)

- **질문:** 명시적 `memo(TaskRow)`와 안정된 콜백(A2)이 기본 앱 A0보다 실제 TaskApp 갱신 시간을 줄이는가? 그리고 memo 지원 엔진이 memo를 쓰지 않는 A0를 느리게 하지 않는가?
- **비교군:** `task-e7-a0-v1`(engine `3e9a48c`, app `9b52323` A0), `task-e8-a0-v1`(engine `0855612`, 같은 A0 app), `task-e8-a2-v1`(engine `0855612`, app = 기본 `TaskApp`을 A2로 바꾼 후보 커밋). 앱 효과는 E8 고정 A0→A2, 엔진 효과는 A0 고정 E7→E8로만 읽는다.
- **기준:** 사전 비교 계획의 허용 범위. 앱: median `max(5%, 0.5ms)`, p95 `max(10%, 1ms)`. 엔진: median `max(5%, 1ms)`, p95 `max(10%, 2ms)`. 기준을 결과에 맞춰 바꾸지 않는다.
- **탐색(1세션):** persistent draft·counter·crud·search·sort·move × 10/100/1,000. 54개 브라우저 프로세스, 약 10분, **상한 `--max-minutes=30`**. 채택 근거로 쓰지 않는다.
- **확대(조건부):** 탐색에서 100·1,000개 crud 하위 action(이름 수정·완료 상태 변경)의 median이 줄고 명백한 회귀가 없을 때만, 독립 3세션 · 9개 workload persistent + fresh × 10/100/1,000(**상한 60분**)로 확인한다. 허용 범위 초과 조건은 n=180 새 3세션으로 보충하고, 보충에서도 재현되면 A2를 기본으로 채택하지 않는다.
- **10,000개는 실행하지 않는다**(사용자 지시).
- **채택하지 않을 때:** 기본 `TaskApp`을 A0로 되돌리는 revert 커밋을 남기고 A2는 비교용 변형으로 유지한다. memo 엔진 지원은 A0 고정 E7→E8에 회귀가 없을 때만 남긴다.
- **중단:** oracle 실패·상한 도달·실행 오류 시 원자료를 보존하고 종료. 자동 후속 없음.

## 탐색 결과와 확인 계획 (탐색 뒤, 확인 실행 전 기록)

- **탐색 결과(`followup-rowmemo-explore-v1`, 1세션, 9분 39초, 54개 조건 oracle 통과):** E8 고정 A0→A2는 48개 판정 조건 모두 median 감소(−11.8~−83.1%), 앱 허용 범위 초과 0건. 반면 A0 고정 E7→E8은 48개 중 17개가 엔진 허용 범위를 넘었다(예: 1,000개 crud 전체 +15.5%, 10개 counter 1.50→3.10ms). A0에서 엔진 차이는 행마다 WeakSet 조회 한 번뿐이라 원인을 확정할 수 없다. 1세션이므로 회귀나 잡음으로 단정하지 않는다.
- **리뷰 반영:** 코드 리뷰(차단 없음)의 지적을 반영한 엔진 `E9`(symbol 키 비교, null props 방어, memo 재사용의 별도 카운터·trace 이름, 문서화)로 확인한다.
- **확인:** `task-e7-a0-v1`, `task-e9-a0-v1`(engine E9, app `9b52323`), `task-e9-a2-v1`(engine E9, app = A2 기본 소스) 독립 3세션, 9개 workload persistent + fresh × 10/100/1,000. 예상 약 35분, **상한 60분**.
- **판정:** (1) A0 고정 E7→E9에 엔진 허용 범위 초과가 있으면 해당 조건을 n=180 보충하고, 재현되면 memo 엔진 지원을 기본 경로에 두지 않는다. (2) E9 고정 A0→A2에 앱 허용 범위 초과가 있으면 n=180 보충하고, 재현되면 A2를 기본으로 채택하지 않는다. 기준은 바꾸지 않는다.
