# M0~M1 구현·검증 기록

- 날짜: 2026-11-07 (Asia/Seoul)
- 기준: 사용자가 확정한 「Mini React B안 — 최종 구현 명세서 및 단계별 체크리스트」와 공식 W11 요구사항.
- 시작 상태: `phase1`, `bdea95c` (`first commit`), README만 존재, 작업 트리 변경 없음.
- 이번 범위: 현재 저장소의 M0 기술 계약과 M1 독립 후보 구현. 다른 팀원의 구현·합의·잔여 일정은 확인하지 않았다. M2 기준 구현 선정은 진행하지 않았다.
- 결론: M1의 지정 7개 테스트 ID와 Chromium 기본 기능 검증 완료. M0의 팀 확인 항목과 M1의 팀 제출 Gate는 별도 확인이 필요하다.

## M0 계약과 체크리스트

- [ ] 팀원 전원의 공식 요구사항 확인 — 현재 작업에서는 공식 요구사항을 읽고 구현에 반영했다. 팀원 확인을 대신하지 않는다.
- [ ] State/Hook 루트 제한·공통 엔진 재사용의 팀 합의 — 코드와 테스트로 제한을 구현했으며 팀 확인은 미확인이다.
- [x] 지원 범위·빈 자식·key·단일 root 계약 명시 — 아래 범위표와 최종 명세의 지원표를 사용한다.
- [x] VDOM / MountView / PatchPlan / HookSlot / TraceEvent 계약을 [types.ts](../src/core/types.ts)에 제공.
- [x] 과제 필수·B안 후속 기능 구분 — M1 구현과 미구현 항목을 별도로 기록.
- [x] 공통 [fixture](../tests/fixtures/helpers.ts)와 `dev`, `typecheck`, `test`, `test:browser`, `build`, `preview` 명령 확정.
- [x] [TraceSink](../src/observe/trace.ts) 진입점 정의. 실행 사실만 전달하며 UI·ring buffer·성능 비교는 후속 단계.
- [ ] 팀 잔여 기간·독립 구현 종료 시점 합의 — 정보가 없어 완료 처리하지 않았다.

기술 계약은 비교 가능한 형태로 준비했다. **팀 합의까지 포함한 M0 전체 Gate 완료를 주장하지 않는다.**

| 계약 | 이번 코드의 의미 |
|---|---|
| VRoot | wrapper를 새로 만들지 않는 container의 자식 목록 |
| VNode | DOM 참조 없는 동결 데이터. element/text/comment, 공백·빈 텍스트 유지 |
| MountView | DOM 없는 논리적 ref 트리. 순수 Diff 입력 |
| MountHandle | mount별 `Map<ref, Node>`와 `WeakMap<Node, ref>`, revision, disposed/faulted 상태 |
| key | h의 string/number는 String으로 정규화. capture는 data-key 원문. 형제 중복·빈 key 거절 |
| identity | 위치가 같아도 key, node kind/tag, 컴포넌트 경계 type/key, 반환 host key가 바뀌면 교체 |
| 빈 자식 | null/undefined/boolean → comment placeholder. 0, 빈 문자열은 text |
| 컴포넌트 | 루트만 Hook 호출. 자식은 props만 받으며 하나의 host/text/빈 결과 반환 |
| Patch | detached create → remove → update → 오른쪽부터 ref/anchor 배치 → 폼 동기화 |
| History | DOM·mount ref 없는 VDOM snapshot. 현재 테스트 DOM 재캡처 후 Undo/Redo |
| Hooks | 호출 순서의 배열 슬롯, 슬롯을 캡처한 stable setter, 후보값은 commit 성공 후 확정 |
| Effect | DOM commit 후 같은 동기 flush에서 모든 cleanup → 모든 setup. paint 이후 실행 보장 없음 |
| Memo | Object.is deps 비교, 직전 결과 1개 보관. 자식 자동 memo는 없음 |
| 오류 | render/updater/Memo 실패는 마지막 정상 상태·화면 보존. DOM 예외는 faulted 처리; 전체 rollback 없음 |

## 구현 범위와 남은 작업

| 항목 | M1 현재 상태 | 후속 작업 |
|---|---|---|
| DOM/VDOM | HTML allowlist, text/공백/comment, 빈 root, 여러 mount 지원 | M3 전체 지원표 회귀 |
| Diff | 위치 기반. 같은 위치의 identity/type 불일치 시 교체 | M4 keyed Greedy/LIS. 재정렬 identity 보존은 아직 보장하지 않음 |
| Patch | stable ref/anchor, stale/wrong mount 거절, 실제 host 호출 카운터, subtree 이벤트 정리 | M3 전체 계획 shape 검증·fault 복구·복잡한 폼 검증 |
| 편집기 | 텍스트 직접 편집, inert HTML 검사 후 편집 영역 연결, Patch/Undo/Redo/초기화 | M7 composition 보호·IME 수동 검증 |
| 입력 경계 | script/inline on*/위험 scheme/SVG·MathML/custom 태그 거절 | srcset·CSS url()·외부 form 속성은 현재 지원 안 함 |
| 폼 | input/checkbox/textarea/select 기본 snapshot, 카운터의 controlled 입력, 초기 uncontrolled 처리 | radio/file 입력 거절. controlled no-op 복원·모드 전환 전체 계약·focus/selection/IME 미완료 |
| State | 루트 슬롯, lazy init, stable setter, FIFO 동기 처리, Object.is | M5 microtask Batching. +1×3은 현재 commit 3회 |
| Effect | deps·cleanup, 오류 후 다른 cleanup 진행, Effect setter 후속 flush, unmount 정리 | M3/M7 전체 예외·비동기·자원·IME 보류 검증 |
| Memo | deps별 계산값 재사용 | M5 동일 expression의 resolver/Diff 생략 |
| Trace | diff/patch/render/enqueue/effect/error 진입점, observer 예외 격리 | M6 cause 연결·ring buffer·Inspector·benchmark |
| 앱 | 카운터/이름 입력/순수 Summary/Memo/문서 제목 Effect | M7 목록 CRUD·검색·정렬 앱 |
| 품질 | 로컬 설치·테스트·빌드·Chromium 기능 smoke | CI, 보조 브라우저, 실제 IME, 공개 배포는 미수행 |

M1은 최종 B안 전체의 완료가 아니다. 지원하지 않는 입력을 일부 명시적으로 거절하는 작은 기준 구현이다. 최종 명세의 Greedy/LIS·microtask 옵션을 M1에 구현한 것처럼 노출하지 않는다. 현재 `DiffOptions.strategy`는 `positional`만 받는다.

## 핵심 원리와 코드 읽는 순서

1. [types.ts](../src/core/types.ts) → [capture.ts](../src/core/capture.ts): DOM은 변할 수 있으므로 읽은 값만 별도 동결 VDOM으로 남긴다. DOM 연결은 snapshot 밖의 mount가 소유한다. 같은 VDOM을 두 영역에 렌더해도 실제 노드는 별개다.
2. [reconcile.ts](../src/core/reconcile.ts) → [patch.ts](../src/core/patch.ts): Diff는 변경 계획만 만든다. 동일 위치·호환 identity는 ref를 재사용한다. Patch는 ref로 실제 노드를 찾아 필요한 텍스트·속성만 바꾼다. 삽입은 오른쪽부터 anchor를 확보하므로 앞쪽의 삭제로 index가 바뀌어도 대상을 혼동하지 않는다.
3. [controller.ts](../src/editor/controller.ts) → [history.ts](../src/editor/history.ts): 사용자가 테스트 DOM을 직접 편집했으므로 Undo 직전에 다시 읽어야 한다. 새로 추가한 미확정 X도 현재 view에 포함시킨 후 과거 snapshot으로 Patch해야 X가 제거된다. History cursor는 두 영역 적용이 끝난 뒤 이동한다.
4. [FunctionComponent.ts](../src/runtime/FunctionComponent.ts) → [hooks.ts](../src/runtime/hooks.ts): 함수의 지역 변수는 매번 새로 생기지만 인스턴스의 hooks 배열은 남는다. 첫 번째 useState는 슬롯 0, 두 번째는 슬롯 1에 연결한다. setter는 루트와 자신의 슬롯 번호를 기억한다. 후보 상태/Hook을 만들어 렌더하고, 공통 commit이 성공한 다음 확정한다.
5. [resolve.ts](../src/runtime/resolve.ts): 루트 render가 끝나면 Hook dispatcher를 끈 뒤 자식을 평가한다. 자식 Hook은 오류가 되고 props만 사용하는 구조가 유지된다. 컴포넌트 경계 정보를 Host VDOM에 남겨 같은 tag라도 type이 바뀌면 교체할 수 있다.
6. `useEffect`는 성공한 commit 뒤 정리·설정을 수행한다. `useMemo`는 deps가 같으면 직전 계산값을 돌려준다. 값 재사용과 DOM 재사용은 별개다. M1에서는 Memo로 expression을 보관해도 resolver의 자식 함수 평가는 생략하지 않는다.

작게 추적할 예: 카운터 `+1` 클릭 → stable 이벤트 wrapper가 최신 handler 호출 → 슬롯 0에 함수형 action 저장 → 후보 count 계산 → root/순수 Summary 실행 → p/output text와 handler 계획 → 공통 commit → hooks 확정 → 이전 제목 cleanup → 새 제목 Effect setup.

다음 단계는 같은 fixture로 팀 후보를 비교하는 M2다. M2 선택 뒤 M3의 전체 정확성 계약을 검증하고, 이후에 M4/M5 최적화를 연결한다.
